# 배포본 QA 보고서

[English](QA_REPORT.md) · [README](../README-KR.md)

기준일: **2026-09-10**. 본 보고서는 데이터 준비 패키지를 점검한 기록이며 시뮬레이터 검증이 아니다.

## 실행한 점검
Python 3.13.5와 jsonschema 4.26.0 환경에서 점검했다. 오프라인 단위 테스트 **26개**는 전류 부호의 명시, 온도 범위, 허용된 수식만 평가하는 기능, 경로 이탈 차단, Git blob 해시, 변조된 내용 거부, 허용된 출처 URL, 동봉 데이터 수량 및 출처 제약을 확인한다. 실제 콘솔 출력은 [unit_tests.txt](unit_tests.txt)에 저장했다.

[패키지 검증기](../scripts/validate_package.py)는 출처·자료·요구 항목의 ID 중복, 출처 참조, 영·한 문서와 자료 카드의 대응, 로컬 Markdown 링크, 구형 데이터의 의미와 단위 변환을 점검한다. JSON Schema 정의 4개의 구조를 확인하고, 해당하는 스키마 3개를 실제 셀·매개변수·정규화 기준 곡선 레코드에 적용한다. 현재 공식 BPX 표준에 대한 파일 적합성을 인증하는 검사는 아니다. 실행 결과는 [package_validation.json](package_validation.json)에 있다.

[수치 점검](numeric_audit.json)은 확보된 구간에만 사다리꼴 적분을 적용한다. 결과는 공인된 전체 시험 용량·에너지나 차량 주행거리가 아니다. NMC 기준 배열 두 개의 마지막 전압은 명목 하한 차단 전압보다 높으며, 누락된 끝부분을 생성하거나 외삽하지 않았다.

점검 환경에서 변환과 수치 점검을 반복 실행했고, 생성된 데이터·산술 보고서의 파일 해시가 동일했다. 부동소수점 적합식 표가 모든 Python 버전·운영체제에서 바이트 단위로 같다고 보장하지는 않는다. 데이터를 다시 생성하기 전에 배포본 체크섬을 확인한다.

## 수집·출처 검증의 한계
[수집 스크립트 보고서](downloader_dry_run.json)는 **드라이런**이며 실제 다운로드 성공 기록이 아니다. About:Energy의 불변 Git blob 16개를 목록화했다. [원본 비교](original_comparison.json)는 BPX 두 개 모두 `not_checked_raw_file_missing` 상태다. 원본과 내용 스냅샷의 의미·바이트 동일성, 전사의 완전성, 다운로드 성공 경로는 **검증하지 못했다**.

내용 스냅샷과 파생 파일에는 출처와 증거 유형을 남겼다. 일정한 298.15 K 값은 기준 온도로 저장하고, 표면·내부 온도 실측 필드는 null로 유지했다. 필요 데이터 항목을 목표 셀 실측값으로 바꾸지 않았고, 공개 적합식에서 만든 표는 계산 자료로 구분했다.

## 로컬 배포본 무결성
[SHA256SUMS.json](../metadata/SHA256SUMS.json)은 업스트림 원본이 아니라 로컬 배포 파일의 지문이다. 자기 자신, 원본 수집 폴더, Git 내부 자료, Python 캐시는 제외한다. `python scripts/validate_package.py --verify-checksums`로 확인한다. 변경 이유를 검토한 뒤에만 매니페스트를 다시 만든다. 설명할 수 없는 해시 불일치를 덮어쓰는 용도로 재생성하지 않는다.

동봉 검증 보고서는 체크섬 매니페스트보다 먼저 작성되어 `checksum_verification`이 `not_requested`다. 그 뒤 체크섬을 검사한 결과는 이미 해시된 보고서에 다시 쓰지 않는다. 이 순서는 보고서 변경 때문에 자기 체크섬이 계속 깨지는 순환을 피한다.

## 입증하지 않은 사항
셀·팩 해석기, 매개변수 보정, 열·열화·파손 예측, 독립 홀드아웃 결과, 실행 속도 및 OEM 디지털 트윈 충실도를 시험하지 않았다. 소프트웨어·데이터 QA는 과학 모델 검증과 다르다. GitHub 저장소를 변경하지 않았으며, 외부 포털의 동의나 접근 신청 양식을 제출하지 않았다.
